# Adversarial audit, 2026-10-19 — merged findings

Three independent auditors, same brief (`audit-2026-10-19/AUDIT-BRIEF.md`), told to find
leaks and eval bugs rather than confirm: Claude Opus 5.5, Codex GPT-6.1-Sol (high),
Gemini 3.8 Flash (high). Raw reports and probe scripts are in `audit-2026-10-19/`.
No trained checkpoints existed (`results/` was empty), so every experiment used tiny
untrained pairs with live links. Nothing here re-measures the headline numbers.

**Bottom line.** No leak was found in the safe-mask fusion. All three auditors checked it
independently, in both directions and for all signals. The split-recall task is sound.
The weak points are elsewhere:
- **Attribution:** what "expert-level" transmission actually shows.
- **Data hygiene:** selection on test data, and an ordinary-text eval that isn't held out.
- **Stale results:** some numbers in the docs still come from the leaky-mask runs.
- **Weak audit tool:** the leak-audit script would pass a leaky model.

Every checkpoint must be regenerated anyway, so fix these first and train once.

**New, found while fixing (both fixed):**
- **float64 broke causality.** `nn.MultiheadAttention` mishandled the float32 `-inf` causal mask in float64, so the base model read the future (4e-2). The masks are now boolean, and a test covers fp32/fp64/bf16.
- **float32 GPU "leak".** The first GPU gate run flagged about 0.3% of positions in BOTH directions at ~1e-3 on the safe experts variant. float64 on the same GPU gives 1.8e-15, so this was rounding that differs between batch shapes and flips near-tied top-k routing, amplified by the N(0,1) expert-ID embeddings. It is not a leak, but the effect matters: expert-tagged buses are sensitive to routing near-ties.

## Minor / notes

- **`safe_mask` isn't enforced in `forward`.** Building a pair with `safe_mask=True` and then calling `pair(...)` directly uses the leaky mask (Codex measured a logit difference of 0.14). The headline paths all call `run_pair`, so this is a hazard for future code. (all three)
- **The enrichment ratios ("×6.2/×5.5") use the wrong baseline.** The denominator counts future and padding entries. (Codex, demonstrated) `blammoe/toy/fused.py:337-343`
- **Bootstrap edge case.** It counts 0/0 resamples as accuracy 0: rows `[[0,0],[1,1]]` give a CI of [0, 1]. (Codex, demonstrated) `blammoe/stats.py:24,37`
- **Metric wording.** The headline numbers are teacher-forced *digit* accuracy. A 4-digit answer carries about 13.3 bits, not 3. Report exact-answer match too. The eval has 273 A-needs-B and 310 B-needs-A answers. (Codex)
- **"Hiding other experts costs <2 points" is within noise.** The effective n is about 273 answers, so ±2.6 pp. Report bootstrap CIs. (Claude)
- **Disputed:** Gemini #10, that `char_distance_buckets` uses closed ends rather than token ends. That's a design choice, not a leak: a token is only readable once closed, and by then its true end is fixed. No action needed.

## Checked and clean (consensus)

- **Safe-mask causality, both directions, all signals.**
  - Claude: a probe that changes the text after a cut point gave max |Δlogit| 7.5e-8 over about 110k positions for experts/moe/resid × rel_pos.
  - Positive control: with `safe_mask=False` the probe flags the leak at 1.5e-2 to 4.6e-2, in A's direction only. That's the documented mechanism, and it shows the probe is sensitive.
  - Codex (8 cases, including hiding) and Gemini each found the same independently.
- **`closed_ends`.** It matches the pre-tokenizer. 156,017 finalized prefix tokens were identical to the full-text tokenization (Codex).
- **Split-recall construction.** Values are masked in exactly one view; keys are unique; digits are single tokens in both tokenizers; chance is 10% per digit (largest fixed-digit rate 11%); train seed 4242 and eval seed 2025 are disjoint.
- **Expert bus and hiding.** The bus carries routed-only, pre-weight expert outputs. Hidden entries get exactly 0 attention, `rel_pos` included.
- **POC 96.5%.** It uses `expert_routed` for A's source; the dense variant is reported separately.
